## Summary

Implement QC Inspection pass/fail flow with 6 QC statuses (PENDING_INSPECTION, PASSED, FAILED, ON_HOLD, REWORK_REQUIRED, SCRAPPED). QC Inspector can pass units (→ AVAILABLE stock, QC_RELEASE movement) or fail units with 3 actions (SCRAP → SCRAPPED + SCRAP movement, HOLD → ON_HOLD + QC_HOLD movement, REWORK → REWORK_REQUIRED + stock stays). Failed lots are terminal — only pass feeds downstream. Implements clean architecture 4-layer quality module with jOOQ persistence, MapStruct DTO mapping, and full integration tests.

## Phase 0: Research

**No unknowns to research.** All technical decisions already made during previous conversation:

| Decision | Value | Rationale |
|----------|-------|-----------|
| QC statuses | PENDING_INSPECTION, PASSED, FAILED, ON_HOLD, REWORK_REQUIRED, SCRAPPED | 6 statuses per URS |
| QC actions | SCRAP, HOLD, REWORK | 3 actions, stored in qc_actions lookup table |
| Movement types | QC_RELEASE, QC_HOLD, SCRAP | QC_RELEASE là tên chuẩn cho movement pass QC |
| Stock statuses | QUALITY_INSPECTION, AVAILABLE, ON_HOLD, SCRAPPED | Existing seed data |
| pass() → stock | QUALITY_INSPECTION → AVAILABLE | Movement QC_RELEASE |
| fail(action=SCRAP) → stock | QUALITY_INSPECTION → SCRAPPED | Movement SCRAP |
| fail(action=HOLD) → stock | QUALITY_INSPECTION → ON_HOLD | Movement QC_HOLD |
| fail(action=REWORK) → stock | QUALITY_INSPECTION (giữ nguyên) | No movement |
| Remaining quantity | inspection.quantity - SUM(results.quantity) | Computed in service, not a DB column |
| REWORK counting | Counted as processed (reduces remaining) | Stock stays QUALITY_INSPECTION |
| All quantities | BigDecimal / NUMERIC(18,4) | Team standard |
| DB action column | VARCHAR(50) changed to FK action_id → qc_actions(id) | Via migration V20260728032200 |
| Fail = terminal | SCRAP/HOLD/REWORK lots stuck | Downstream handled in future features |
